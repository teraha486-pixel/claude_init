# 개인 작업 규칙

## ⚠️ 절대 준수 규칙 (실수 방지)

### Git 브랜치 규칙
- **develop, master에 절대 직접 커밋 금지**
- 커밋 전 반드시 `git branch --show-current`로 브랜치 확인
- 작업 브랜치 없으면 새로 생성: `feature/{작업명}`
- 기존 작업 브랜치 있으면 반드시 그 브랜치에서 작업

### 워크트리 확인 (브랜치 전환 전 필수)
- **코드 작업 시 현재 브랜치 ≠ 타겟 브랜치이면 반드시 사용자에게 확인:**
  > "지금 {현재브랜치}에서 작업 중인 거 있으세요? 워크트리로 따로 빼서 할까요, 브랜치 전환해도 될까요?"
- 워크트리 선택 시: `git worktree add ../{프로젝트}-{작업명} {타겟브랜치}`
- 브랜치 전환 선택 시: 기존처럼 checkout
- 현재 브랜치 = 타겟 브랜치면 질문 없이 바로 진행
- **`/do` 사용 여부와 관계없이** 모든 코드 작업에 적용

### 커밋 작업자 이름
- **작업자 이름: 근형** (복성 아님!)
- 커밋 메시지 형식: `[근형] 작업내용`
- **Co-Authored-By 절대 금지!** (적지 마라)

### push 후 필수
- **gc 실행**: `git reflog expire --expire=now --all && git gc --prune=now`
- 안 하면 고아 커밋 쌓여서 느려짐

### docs 폴더 구조
- 관련 작업 문서는 **반드시 해당 폴더 안에** 생성
- 예: `docs/룸패킷_memberId_제거/xxx.md`
- docs/ 루트에 직접 파일 생성 금지 (폴더로 묶인 작업은 폴더 안에)

### 작업 연속성 유지
- 작업할 때마다 **위키 + md에 기록** (다음 세션에서 이어서 작업 가능하도록)
- 기록 필수 항목: 브랜치명, 커밋 해시, 진행 상황, 남은 작업
- 세션 시작 시 **위키에서 이전 작업 확인 후 이어서 진행**

### 🚨 주간보고 주(週) 경계 = 금요일 시작 ~ 목요일 끝 (절대 헷갈리면 안 됨!)
- **한 주 = 금요일 ~ 다음 목요일** (금요일 리더회의 발표 → 그 다음 목요일 마감)
- 보고서 제목의 날짜 = 해당 주의 **마지막 날(목요일)**
- **금~목 작업** → 그 목요일 날짜 보고서에 기록
- 예: 금 2/13 ~ 목 2/19 사이 작업 → **2/19 보고서**에 기록
- 예: 금 2/20 ~ 목 2/26 사이 작업 → **2/26 보고서**에 기록
- **판단 공식**: 오늘 요일이 금(5)~목(4)이면 → **다음 목요일 날짜 페이지** (오늘이 목요일이면 오늘 날짜)
- **코드로 계산**: `days_ahead = (3 - today.weekday()) % 7; if days_ahead == 0 and today.weekday() == 3: 오늘; else: today + days_ahead`

### 주간보고 위키에 작업 댓글 남기기 (빠뜨리면 안 됨!)
- **작업 완료 시 반드시 해당 주차 주간보고 위키 페이지에 댓글 남기기**
- `/do` 사용 여부와 관계없이 **모든 작업에 적용** (불필요한 건 사용자가 삭제)
- **페이지 찾기**: `get_child_wiki_list(wiki_id="3051057878725260241", parentPageId="4250340996968691291")` → 위 주 경계 규칙에 따라 해당 목요일 날짜 페이지
- **카테고리 분류 (H2 제목 뒤에 반드시 표기)**:
  1. 관련 두레이 업무가 있으면 → 웹보드개발랩-전체공유(`2779708918315063486`) 프로젝트에서 "N월 반영업무" 조회 (`subjects: "반영업무"`)
  2. 해당 업무가 월별 반영업무의 하위업무이면 → `(N월반영)`
  3. 하위업무에 없지만 반영 대상으로 보이면 → 사용자에게 "이 업무 N월 반영업무 하위로 넣을까요?" 제안
  4. 인프라/서버환경/장비 관련 → `(인프라)`
  5. 그 외 → `(기타업무)`
  6. 판단 어려우면 → 이번 주/지난 주 기존 댓글 패턴 참고
- **타이밍**: 작업 끝났을 때, "됐어/끝/다음 작업" 전환 시, `/do` 완료 시
- 댓글 형식:
  ```
  ## {날짜} 작업 내역 ({카테고리})
  ### {작업명}
  - **내용**: {2~3줄 요약}
  - **커밋**: `{해시}` - {설명}
  - **브랜치**: {브랜치명}
  ```

## 위키 작업 문서 규칙 (/wiki)
작업 진행 시 두레이 위키에 문서 작성 → 사용자가 복붙하는 방식

- **위키**: @zman 개인 위키 (`wiki_id: 3051057878725260241`)
- **기본 페이지**: claude code (`4248918788553579171`)
- **URL**: `https://nhnent.dooray.com/wiki/3051057873186173159/{page_id}`

### 작업 시작 시 구조
```
claude code/
└── {작업명}/
    ├── 클라이언트_가이드    ← 클라팀 전달용 (복붙)
    └── 두레이_댓글_초안     ← 댓글 템플릿 (복붙)
```

### 활용
- **두레이 업무에 직접 댓글 달지 않음** → 위키에 초안 작성
- 사용자가 검토 후 복붙
- 기록이 남아 나중에 참조 가능

### 두레이_댓글_초안 페이지 규칙
- **새 내용 추가 시**: 본문에 날짜별 섹션으로 추가 (예: `## 2026-01-22 xxx 안내`)
- **본문 업데이트 시**: 기존 내용 + 새 내용 통합 정리
- **업데이트 히스토리**: 본문 하단에 테이블로 기록 (날짜, 댓글 링크, 변경 요약)
- **cc 태그 사용 금지**: 복붙 시 사용자가 직접 추가

## 작업 완료 규칙
1. 코드 작성 → 빌드 테스트까지만 (배포/실제 테스트는 범위 외)
2. **프로젝트 docs 폴더에 작업 가이드 md 작성** (필수)
   - 파일명: `{기능명}_{작업내용}.md`
   - 내용: 커밋 번호, 두레이 링크, API 목록, 수정 파일
3. 개인 설정 변경 시 `~/init/`에 push
4. **주간보고 위키에 작업 댓글 자동 기록**

### 작업 완료 보고 (절대 누락 금지!)
- **모든 작업이 끝나면 번호 매겨서 완료 내역을 사용자에게 보고**
- 사용자가 묻기 전에 먼저 알려줘야 함!
- 보고 형식:
  ```
  ## 완료 내역
  1. 빌드 성공 (hangame-poker-server)
  2. 유닛테스트 통과
  3. 위키 작성: [페이지명](URL)
  4. 주간보고 댓글: [페이지명](URL)
  5. 커밋: `해시` - 메시지 → 레포: {레포명}, 브랜치: {브랜치명}
  6. 푸시: {레포명} → {브랜치명}
  7. docs 작성: {파일경로}
  ```
- **커밋/푸시는 반드시 레포명 + 브랜치명 명시**
- 해당 없는 항목은 생략 가능, 있는 건 절대 누락 금지
